# Feature Specification: 專案簡化

**Feature Branch**: `003-simplify-project`  
**Created**: 2026年2月6日  
**Status**: Draft  
**Input**: User description: "我希望這個專案簡單一點"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 簡化核心工作流程 (Priority: P1)

開發者或專案管理者能夠以最少的步驟完成日常任務，系統僅保留最關鍵的功能，移除冗余或很少使用的選項。

**Why this priority**: 這是最直接影響使用者體驗的改進，能立即降低學習曲線並提高生產力。

**Independent Test**: 可以透過讓新使用者完成核心任務（如記錄工時、查看報表）來測試，測量完成時間和錯誤率。

**Acceptance Scenarios**:

1. **Given** 使用者首次登入系統，**When** 查看主介面，**Then** 僅顯示核心功能選項（最多3-5個主要選單項目）
2. **Given** 使用者需要記錄工時，**When** 點擊工時記錄功能，**Then** 在單一畫面內完成所有必要資訊輸入，無需多步驟流程
3. **Given** 使用者需要查看報表，**When** 選擇報表功能，**Then** 預設顯示最常用的報表類型，無需複雜篩選

---

### User Story 2 - 減少配置複雜度 (Priority: P2)

系統管理者能夠使用預設配置快速設定和部署系統，僅在必要時才需要調整進階設定。

**Why this priority**: 降低系統部署和維護的門檻，減少出錯機會。

**Independent Test**: 新管理者能在30分鐘內完成系統初始設定並使其可用。

**Acceptance Scenarios**:

1. **Given** 管理者首次部署系統，**When** 使用預設配置啟動，**Then** 系統能立即運作，無需手動配置資料庫、驗證等基礎設施
2. **Given** 系統已運行，**When** 管理者需要調整設定，**Then** 所有設定集中在單一配置檔案中，使用清晰的文件說明
3. **Given** 管理者部署更新，**When** 執行部署指令，**Then** 系統自動處理資料庫遷移和依賴更新

---

### User Story 3 - 簡化資料模型 (Priority: P3)

系統使用最精簡的資料結構，移除不必要的關聯和欄位，讓資料關係更容易理解。

**Why this priority**: 簡化資料模型可以提高系統效能並降低維護成本，但不如直接的使用者體驗改進重要。

**Independent Test**: 資料模型圖能在單頁 A4 紙上清晰呈現，開發者能在15分鐘內理解所有實體關係。

**Acceptance Scenarios**:

1. **Given** 開發者查看資料模型，**When** 計算核心實體數量，**Then** 不超過 10個核心實體
2. **Given** 系統儲存工時記錄，**When** 查看資料表欄位，**Then** 每個實體的欄位數量控制在10個以內，僅保留必要資訊
3. **Given** 開發者需要擴展功能，**When** 閱讀資料模型文件，**Then** 所有實體和關係都有清晰的業務說明

---

### Edge Cases

- 當簡化過程需要刪除現有功能時，如何處理已有的用戶資料？
- 如何確保簡化不會影響系統的核心業務邏輯正確性？
- 當使用者需要被刪除的功能時，系統該如何引導他們使用替代方案？
- 如何在簡化和保留必要彈性之間取得平衡？

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系統 MUST 僅保留核心業務功能（使用者管理、工時記錄、基本報表）
- **FR-002**: 系統 MUST 將相似功能合併到單一介面中，避免功能分散
- **FR-003**: 系統 MUST 為所有常用操作提供合理的預設值，最小化必填欄位
- **FR-004**: 系統 MUST 使用單一、一致的導航結構，避免多層級選單
- **FR-005**: 系統 MUST 將所有配置整合到單一配置檔案中
- **FR-006**: 系統 MUST 提供自動化的設定和部署流程
- **FR-007**: 系統 MUST 簡化資料模型，移除冗余關聯和很少使用的欄位
- **FR-008**: 系統 MUST 在簡化過程中保留現有資料的完整性
- **FR-009**: 系統 MUST 提供清晰的錯誤訊息，避免技術術語
- **FR-010**: 系統 MUST 記錄所有簡化變更，以便必要時回復

### Key Entities

簡化後的核心實體（以時間追蹤系統為例）：

- **使用者（User）**: 系統使用者，包含基本身份資訊（姓名、電子郵件、角色）
- **工時記錄（Timesheet）**: 工作時間記錄，包含日期、時數、專案/任務關聯、狀態
- **專案（Project）**: 工作專案，包含名稱、描述、狀態
- **部門（Department）**: 組織單位，包含名稱、主管
- **報表（Report）**: 預先定義的報表類型，簡化到2-3種最常用的報表

### Non-Functional Requirements

**Performance**:
- **NFR-001**: 頁面載入時間 < 1 秒（p95），透過減少不必要的資料查詢和簡化 UI 組件
- **NFR-002**: API 回應時間 < 200ms（p95），移除複雜的資料關聯查詢
- **NFR-003**: 系統支援至少100個並行使用者（適合中小型組織）

**User Experience**:
- **NFR-004**: 新使用者能在10分鐘內完成首次工時記錄，無需培訓
- **NFR-005**: 主要功能點擊次數不超過3次
- **NFR-006**: 所有表單必填欄位不超過4個
- **NFR-007**: 錯誤訊息使用通俗語言，提供明確的修正建議

**Code Quality**:
- **NFR-008**: 程式碼覆蓋率維持在 80% 以上
- **NFR-009**: 移除未使用的程式碼和相依套件
- **NFR-010**: 降低循環複雜度，函式不超過15行（除必要例外）

**Testing**:
- **NFR-011**: 所有簡化變更必須有對應的單元測試
- **NFR-012**: 整合測試涵蓋所有保留的核心功能
- **NFR-013**: 提供端對端測試驗證核心使用者流程

**Maintainability**:
- **NFR-014**: 專案文件更新反映簡化後的架構
- **NFR-015**: 建構時間減少至少30%
- **NFR-016**: 第三方相依套件數量減少至少20%

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 新使用者完成核心任務（記錄工時、提交、查看報表）的平均時間從目前基準減少50%
- **SC-002**: 系統部署時間從初始設定到可用狀態少於1小時
- **SC-003**: 使用者介面的主選單項目數量減少到5個以內
- **SC-004**: 程式碼庫大小（行數）減少至少30%
- **SC-005**: 核心資料實體數量減少到8個以內
- **SC-006**: 系統文件的頁數減少到20頁以內，同時保持清晰度
- **SC-007**: 使用者滿意度調查中「易用性」評分提升至4.5/5以上
- **SC-008**: 技術支援請求數量減少40%
- **SC-009**: 新開發者能在1天內理解完整系統架構並開始貢獻程式碼
- **SC-010**: 建構和測試的 CI/CD 流程時間減少至30分鐘以內

## Assumptions *(documented)*

以下是本規格基於使用者需求「希望專案簡單一點」所做的假設：

1. **目標使用者**: 假設主要使用者是中小型組織（50-100人），不需要大型企業級功能
2. **簡化範圍**: 假設簡化涵蓋使用者介面、資料模型、配置和程式碼結構，而非移除整個功能模組
3. **保留功能**: 假設核心功能（使用者認證、工時記錄、基本報表）必須保留
4. **技術棧**: 假設不改變現有技術棧（Vue.js、Spring Boot），僅簡化其使用方式
5. **向後相容**: 假設需要保持與現有資料的相容性，不能破壞已有的工時記錄
6. **部署方式**: 假設系統使用 Docker Compose 部署，簡化應專注於配置和啟動流程
7. **文件語言**: 假設系統支援中文介面和文件

## Out of Scope *(明確界定)*

以下項目明確不在本次簡化範圍內：

1. **完全重寫**: 不進行技術棧替換或系統重構
2. **新功能開發**: 不添加新的業務功能，僅專注於簡化現有功能
3. **效能最佳化**: 除非直接與簡化相關，否則不進行深度效能調校
4. **行動應用**: 不開發原生行動應用，保持 Web 應用形式
5. **國際化**: 不擴展多語言支援（僅中文/英文）
6. **進階報表**: 不保留複雜的自訂報表功能，僅保留2-3種預定義報表
7. **外部整合**: 不新增或簡化與外部系統的整合（如 LDAP、SSO）
