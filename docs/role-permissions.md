# 角色權限矩陣 (Role-Permission Matrix)

> 報工系統 - 完整的角色權限對照表

## 概述

本文件定義報工系統中五種角色的詳細權限，包括功能存取權限、資料存取範圍、操作限制等。

## 角色定義

| 角色代碼 | 中文名稱 | 英文名稱 | 說明 |
|---------|---------|---------|------|
| EXECUTIVE | 管理層 | Executive | 最高權限，負責專案創建、時數審批、總覽管理 |
| PM | 專案經理 | Project Manager | 管理專案與任務、分配工時、追蹤團隊進度 |
| MANAGER | 部門主管 | Department Manager | 查詢部門工時報表、監控部門成員工作狀況 |
| EMPLOYEE | 執行人員 | Employee | 填報工時、完成任務、申請額外時數 |
| HR | 人力資源 | Human Resources | 管理使用者帳號、維護部門資料 |

| 功能 | EXECUTIVE | PM | MANAGER | EMPLOYEE | HR |
|------|-----------|----|---------|---------|----|
| 查看我的工時記錄 | ❌ | ❌ | ❌ | ✅ | ❌ |
| 填報每日工時 | ❌ | ❌ | ❌ | ✅ | ❌ |
| 編輯工時記錄 | ❌ | ❌ | ❌ | ✅ (3工作日內) | ❌ |
| 刪除工時記錄 | ❌ | ❌ | ❌ | ❌ | ❌ |
| 查看團隊工時 | ❌ | ✅ (專案內) | ✅ (部門內) | ❌ | ❌ |
| 匯出工時報表 | ❌ | ✅ | ✅ | ❌ | ❌ |

**資料存取範圍**:
- **EMPLOYEE**: 僅能查看和編輯自己的工時記錄
- **PM**: 可查看專案內所有成員的工時記錄
- **MANAGER**: 可查看部門內所有成員的工時記錄

**業務規則**:
- 每日總工時 ≤ 8小時
- 工作時間超過 6 小時自動扣除 1 小時午休
- 僅能編輯過去 3 個工作日內的記錄
- 工時精度為 0.5 小時（30分鐘）
- 週末和節假日無法填報工時

## 資料隔離策略

### 1. Row-Level Security (行級安全)

不同角色對相同資料表的存取範圍限制：

| 資料表 | 隔離策略 |
|--------|---------|
| **users** | HR 可存取全部；其他角色僅能查看基本資訊 |
| **projects** | EXECUTIVE 可查看全部；PM 僅能查看負責的專案 |
| **tasks** | PM 可查看專案內任務；EMPLOYEE 僅能查看指派給自己的任務 |
| **timesheet_entries** | EMPLOYEE 僅能查看自己的記錄；PM/MANAGER 可查看團隊/部門記錄 |
| **hours_requests** | EXECUTIVE 可查看全部；PM 僅能查看自己的申請 |
| **notifications** | 僅能查看自己的通知 |
| **departments** | 全部角色可查看列表；MANAGER 可查看自己部門詳情 |
| **audit_logs** | 僅系統管理員可存取（未開放給一般使用者） |

### 2. 實作方式

- **@PreAuthorize 註解**: 控制方法級別的權限
- **自訂 PermissionEvaluator**: 複雜的權限判斷邏輯
- **Service 層過濾**: 在業務邏輯層過濾資料

範例：

```java
// Controller 層權限檢查
@PreAuthorize("hasRole('PM')")
@GetMapping("/pm/projects")
public List<ProjectDto> getMyProjects() {
    // Service 會自動過濾只返回當前 PM 負責的專案
}

// Service 層資料過濾
@PreAuthorize("hasPermission(#projectId, 'Project', 'READ')")
public ProjectDto getProjectById(Long projectId) {
    // 自訂 PermissionEvaluator 檢查使用者是否有權存取該專案
}
```

## 權限檢查流程

```
1. 請求進入系統
   ↓
2. JWT Filter 驗證 Token
   ↓
3. 提取使用者角色 (Role)
   ↓
4. SecurityFilterChain 檢查 URL 權限
   ↓
5. Controller @PreAuthorize 檢查方法權限
   ↓
6. Service 層 PermissionEvaluator 檢查資料權限
   ↓
7. Repository 返回資料
   ↓
8. 回應客戶端
```

## 安全最佳實踐

### ✅ DO (應該做)

1. **永遠驗證使用者身份**
   - 除了公開端點，所有 API 都需要 JWT 認證

2. **多層權限檢查**
   - URL 層級（SecurityConfig）
   - 方法層級（@PreAuthorize）
   - 資料層級（PermissionEvaluator）

3. **最小權限原則**
   - 使用者僅能存取必要的資料
   - 預設拒絕，明確允許

4. **審計日誌**
   - 記錄所有關鍵操作（創建、修改、刪除）
   - 記錄審批流程（時數申請審批）

5. **敏感資料保護**
   - 密碼使用 BCrypt 加密
   - JWT Secret 使用環境變數
   - 不在日誌中記錄密碼或 Token

### ❌ DON'T (不應該做)

1. **不要在前端做權限檢查**
   - 前端隱藏按鈕只是 UX 優化，不是安全措施
   - 後端必須強制檢查權限

2. **不要信任客戶端資料**
   - 所有輸入都需要驗證
   - 使用 Bean Validation (@Valid)

3. **不要使用硬編碼的 Secret**
   - JWT Secret 必須從環境變數讀取
   - 不同環境使用不同的 Secret

4. **不要洩漏敏感資訊**
   - 錯誤訊息不應包含系統內部資訊
   - 404 vs 403：使用 404 避免資訊洩漏
